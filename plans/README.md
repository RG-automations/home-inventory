# Animation improvement plans

Generated by an `improve-animations` audit against commit `b2dddbb`. Each
plan is self-contained — see the individual file for full detail, exact code
targets, and verification steps.

| # | Title | Severity | Status | Depends on |
| --- | --- | --- | --- | --- |
| [001](001-native-press-feedback.md) | Fix press feedback silently doing nothing on iOS/Android | HIGH | DONE | — |
| [002](002-consolidate-press-scale-tokens.md) | Consolidate divergent press-feedback scale values into one token | MEDIUM | DONE | 001 |
| [003](003-reduced-motion-support.md) | Add reduced-motion support to SwipeableRow and Modal transitions | MEDIUM | DONE | — |
| [004](004-animate-tree-expand-collapse.md) | Animate location tree expand/collapse instead of teleporting | LOW | DONE | 001 (reuses `PRESS_TIMING_CONFIG`) |
| [005](005-ios-style-drawer-curve.md) | Replace RN's built-in slide animation with an iOS-style drawer curve | LOW | DONE | 003 (reduced motion wired in immediately, not deferred) |

## Recommended execution order

1. **001** first — it's the highest-severity finding (native press feedback
   was silently non-functional) and plan 002 cannot start until
   `lib/press.ts`'s `PRESS_TIMING_CONFIG` exists.
2. **002** next — consolidates the scale tokens onto the now-working
   `AnimatedPressable`. Landing this right after 001 avoids a window where
   the app has working native transitions on 13 files but still-instant
   transitions on the 5 files this plan fixes.
3. **003** can be done in parallel with 001/002 — it touches different files
   (`SwipeableRow.tsx`'s gesture logic and the `Modal` `animationType` props)
   and has no dependency on either.
4. **004** after 001 — it imports `PRESS_TIMING_CONFIG` from `lib/press.ts`,
   which only exists once 001 lands. (A fallback inline value is described
   in 004's plan if you need to do 004 first for some reason, but landing
   001 first is simpler.)
5. **005** last — it's the lowest-leverage finding (a subtle curve
   difference on 4 bottom sheets) and its own plan calls out 003 as an
   optional fast-follow for the new custom-built sheets it introduces (they
   don't inherit `Modal`'s reduced-motion handling from 003 automatically,
   since 005 replaces `Modal`'s `animationType` with a fully custom
   Reanimated transition on those same 4 files).

## Notes

- Every plan was verified against the actual installed package versions in
  this repo (`react-native-reanimated@4.5.1`, `react-native@` per
  `package.json`) before being written — API calls cited (`Easing.bezier`,
  `ReduceMotion.System`, `AccessibilityInfo.isReduceMotionEnabled`,
  `UIManager.setLayoutAnimationEnabledExperimental`) were all confirmed to
  exist in `node_modules` type definitions, not assumed from memory.
- Two findings from the audit were deliberately **not** turned into plans
  because they were rejected during vetting: `Modal transform-origin`
  (React Native's `Modal` is not a trigger-anchored popover, so this
  web-oriented audit rule doesn't apply) and `SwipeableRow`'s gesture logic
  (already correctly implements interruptibility, rubber-banding, and
  velocity handoff — nothing to fix).
- Run `improve-animations reconcile` after landing any of these plans to
  re-check this table's Status column and refresh any file:line references
  that may have drifted.
